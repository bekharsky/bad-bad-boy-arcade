# Рабочие заметки об игре

## Текущее устройство

Golden Blast Helsinki — браузерная игра на JavaScript и Three.js. Vite собирает основную страницу и страницу титров; модели и шрифты лежат в репозитории. Код остаётся модульным без отдельного игрового движка.

- `game.js` связывает интерфейс, состояние раунда и системы игры. `world/frame-clock.js` ведёт симуляцию с фиксированным шагом; пауза и скрытая вкладка сбрасывают накопленное время.
- `maps/index.js` задаёт порядок районов. `world/map-manager.js` заменяет активную карту и предоставляет игровым системам её пространственные запросы. Карта владеет своим декором и ресурсами GPU; при замене они освобождаются.
- `waves.js` и `arena-combat.js` отвечают за волны и наземных врагов. `runner/session.js`, `runner/course.js` и `runner/encounters.js` — за забеги и транспорт. Чайки живут в `seagulls.js` отдельно от волн.
- `spray-system.js` управляет обычной и усиленными струями, `liquid.js` — полётом жидкости и попаданиями. Движение, помощь с прицелом и ввод находятся в отдельных модулях.
- Повторно используемые шаблоны транспорта хранятся в `runner/traffic-models.js`. Каждая карта получает собственные копии ресурсов; целые районы не кэшируются.

Кампания идёт через West Harbor → Baana → Kamppi → Aleksanterinkatu → Senate Square, затем повторяется. Площади используют бой с волнами, Baana и Aleksanterinkatu — забеги. Счёт сохраняется между районами, здоровье восстанавливается. Это стилизованный Хельсинки: география и расстояния изменены ради игры. Подробнее о конкретных зданиях на Aleksanterinkatu — в [заметке об ориентирах](aleksanterinkatu-landmarks.md).

## Локальный запуск и проверка

Нужен Node.js 22. После клонирования:

```bash
npm ci
npm start
```

Адрес сервера показывает Vite. `npm test` запускает тесты, `npm run build` создаёт `dist`, `npm run preview` показывает собранную версию. `?debug=maps` открывает выбор района для ручной проверки, а `?map=baana`, `?map=kamppi`, `?map=aleksanterinkatu` и `?map=senate-square` запускают конкретную карту. Новую геометрию и управление стоит проверять также в браузере на телефоне.

## Карты и ресурсы

Новая карта регистрируется в `maps/index.js`. Её определение задаёт `id`, `name`, границы, старт игрока и точки предметов. Построитель `createMap` добавляет декор в принадлежащий карте корень и возвращает коллайдеры; при необходимости он задаёт здания для прозрачности, движущиеся препятствия, `update()` и `reset()`. Забег дополнительно задаёт `mode: 'runner'`, конфигурацию трассы и `updateRunner()`. Координаты мира измеряются в метрах, ось Y направлена вверх. Ресурсы карты должны освобождаться при её замене; общие шаблоны нельзя освобождать вместе с экземпляром карты.

Подготовленная модель героя — `assets/bad-bad-boy.glb`. Исходная модель для пересборки не требуется при обычной разработке. Если она доступна, модель можно подготовить заново командой `npm run prepare-model -- /path/to/source.glb`. Лицензии и источники ассетов перечислены в [CREDITS.md](../CREDITS.md).

## Публикация

`main` — исходный код, `bekharsky/arcade` — только собранная игра. Каждый push в `main`, включая слияние PR, запускает [Publish arcade](../.github/workflows/publish-arcade.yml): тесты, сборку, обновление `bekharsky/arcade` и прямую публикацию той же сборки в GitHub Pages. В `arcade/source-revision.txt` записан коммит исходников. Повторный запуск доступен через **Run workflow** в GitHub Actions. `npm run publish:arcade` остаётся локальной командой для ручного обновления ветки сборки из чистого `main`, совпадающего с `origin/main`.

Текущие вопросы производительности собраны в [отдельной короткой заметке](performance-review.md).
