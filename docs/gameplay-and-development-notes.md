## Текущее устройство

Piss Deal — браузерная игра на JavaScript и Three.js. Vite собирает основную страницу и страницу титров; модели и шрифты лежат в репозитории. Код остаётся модульным без отдельного игрового движка.

- `game.js` связывает интерфейс, состояние раунда и системы игры. `world/frame-clock.js` ведёт симуляцию с фиксированным шагом; пауза и скрытая вкладка сбрасывают накопленное время.
- `maps/index.js` задаёт порядок районов. `world/map-manager.js` заменяет активную карту и предоставляет игровым системам её пространственные запросы. Карта владеет своим декором и ресурсами GPU; при замене они освобождаются.
- `arena-combat.js` отвечает за гусей, `sleigh-search.js` — за тайник и посты охраны, `gull-flight.js` — за чаек. `runner/session.js`, `runner/course.js` и `runner/encounters.js` ведут забеги и транспорт. Детали из `models/sleigh.js` используются в `sleigh-intro.js`, на финишах и в `sleigh-assembly.js`.
- `spray-system.js` управляет обычной и усиленными струями, `liquid.js` — полётом жидкости и попаданиями. Движение, помощь с прицелом и ввод находятся в отдельных модулях.
- Повторно используемые шаблоны транспорта хранятся в `runner/traffic-models.js`. Каждая карта получает собственные копии ресурсов; целые районы не кэшируются.

Кампания идёт через West Harbor → Baana → Kamppi → Central Station → Aleksanterinkatu → Senate Square. На аренах деталь саней спрятана за зданием. В Baana и Aleksanterinkatu её выдают на финише. Кампания заканчивается после сборки всех шести деталей. Счёт и детали сохраняются между районами, здоровье восстанавливается. География стилизованного Хельсинки изменена ради игры. Подробнее о зданиях на Aleksanterinkatu можно прочитать в [заметке об ориентирах](aleksanterinkatu-landmarks.md).

## Локальный запуск и проверка

Нужен Node.js 22. После клонирования:

```bash
npm ci
npm start
```

Адрес сервера показывает Vite. `npm test` запускает тесты, `npm run build` создаёт `dist`, `npm run preview` показывает собранную версию. `?debug=maps` открывает выбор района для ручной проверки, а `?map=baana`, `?map=kamppi`, `?map=central-station`, `?map=aleksanterinkatu` и `?map=senate-square` запускают конкретную карту. Новую геометрию и управление стоит проверять также в браузере на телефоне.

## Карты и ресурсы

Новая карта регистрируется в `maps/index.js` и получает одну деталь в `models/sleigh.js`. Её определение задаёт `id`, `name`, границы, старт игрока и точки предметов. Для арены добавляется `pickups.sleigh` с координатами тайника. Построитель `createMap` добавляет декор в принадлежащий карте корень и возвращает коллайдеры. При необходимости он задаёт здания для прозрачности, движущиеся препятствия, `update()` и `reset()`. Забег дополнительно задаёт `mode: 'runner'`, конфигурацию трассы и `updateRunner()`. Координаты мира измеряются в метрах, ось Y направлена вверх. Ресурсы карты освобождаются при её замене, общие шаблоны остаются в игре.

Подготовленная модель героя — `assets/bad-bad-boy.glb`. Исходная модель для пересборки не требуется при обычной разработке. Если она доступна, модель можно подготовить заново командой `npm run prepare-model -- /path/to/source.glb`. Лицензии и источники ассетов перечислены в [CREDITS.md](../CREDITS.md).

## Публикация

`main` — исходный код, `bekharsky/arcade` — только собранная игра. Каждый push в `main`, включая слияние PR, запускает [Publish arcade](../.github/workflows/publish-arcade.yml): тесты, сборку, обновление `bekharsky/arcade` и прямую публикацию той же сборки в GitHub Pages. В `arcade/source-revision.txt` записан коммит исходников. Повторный запуск доступен через **Run workflow** в GitHub Actions. `npm run publish:arcade` остаётся локальной командой для ручного обновления ветки сборки из чистого `main`, совпадающего с `origin/main`.

Текущие вопросы производительности собраны в [отдельной короткой заметке](performance-review.md).
